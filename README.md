# Ravidchat

پیام‌رسان وب فارسی، ساخته‌شده با PHP/MySQL و رابط کاربری قالب موجود.

- آدرس: <http://ravid.m.ihweb.ir/>
- ورود/ثبت‌نام: <http://ravid.m.ihweb.ir/auth.php>
- صفحه اصلی بعد از ورود: <http://ravid.m.ihweb.ir/index.php>

## امکانات

- حساب کاربری با ثبت‌نام/ورود، هش bcrypt، نشست PHP و توکن CSRF
- گفتگوی خصوصی، گروه و کانال
- ارسال، پاسخ، ویرایش، حذف نرم و واکنش به پیام
- تیک خوانده‌شدن، شمارنده پیام‌های خوانده‌نشده، تایپ و وضعیت آنلاین
- فایل و تصویر گفتگو (حداکثر ۸ مگابایت) با ذخیره‌سازی خارج از مسیر اجرای کد
- عکس پروفایل و عکس گروه/کانال با تبدیل سرور به WebP
- استوری متن، تصویر و ویدیوی ۲۴ ساعته و بازدید استوری
- تنظیمات هر عضو: سنجاق پیام، بی‌صدا کردن، فقط ادمین‌ها
- پیام‌های ذخیره‌شده، جستجوی کاربر و به‌روزرسانی پروفایل
- همگام‌سازی با polling هر ۳ ثانیه (بدون WebSocket)

## رسانه‌ها و استوری‌ها

- عکس پروفایل و عکس گروه/کانال در سرور با GD به WebP تبدیل می‌شود؛ عکس پروفایل/گروه/کانال به‌صورت مربع و حداکثر ۵۱۲×۵۱۲ ذخیره می‌شود.
- عکس استوری با GD به WebP و حداکثر ۱۰۸۰×۱۹۲۰ تبدیل می‌شود.
- ویدیوی استوری در مرورگر با `MediaRecorder` به WebM تبدیل می‌شود. خروجی حداکثر ۷۲۰×۱۲۸۰ و با نرخ تقریبی ۱٫۵ مگابیت بر ثانیه است.
- منبع ویدیو باید حداکثر ۱۵ ثانیه باشد؛ کلاینت مدت را از متادیتای فایل بررسی می‌کند و سرور مقدار `duration` را حداکثر ۱۵٫۰۵ ثانیه می‌پذیرد.
- حجم هر تصویر/ویدیوی استوری حداکثر ۱۸ مگابایت است (`MAX_STORY_BYTES`). حجم عکس پروفایل/گروه/کانال و فایل‌های گفتگو حداکثر ۸ مگابایت است.
- فایل‌های استوری در `uploads/stories/Y/m/`، عکس‌های پروفایل در `uploads/avatars/` و عکس‌های گروه/کانال در `uploads/chats/` ذخیره می‌شوند.
- استوری‌ها ۲۴ ساعت پس از انتشار منقضی می‌شوند. چون هاست cron ندارد، پاک‌سازی با اولین درخواست بعدی (حداکثر با فاصله‌ی ۵ دقیقه، به‌کمک فایل `uploads/.story-cleanup`) انجام می‌شود و ردیف دیتابیس و فایل رسانه با هم حذف می‌شوند. اگر هیچ درخواستی به سایت نرسد، حذف تا اولین درخواست بعدی به تعویق می‌افتد.

برای نصب تازه، `schema.sql` این ستون‌ها را دارد. در نصب موجود باید ستون‌های زیر یک‌بار اضافه شوند:

```sql
ALTER TABLE users ADD COLUMN avatar_path VARCHAR(255) DEFAULT NULL;
ALTER TABLE chats ADD COLUMN avatar_path VARCHAR(255) DEFAULT NULL;
ALTER TABLE stories
  ADD COLUMN media_type ENUM('image','video') DEFAULT NULL,
  ADD COLUMN media_path VARCHAR(255) DEFAULT NULL,
  ADD COLUMN media_mime VARCHAR(100) DEFAULT NULL,
  ADD COLUMN media_size INT UNSIGNED DEFAULT NULL,
  ADD COLUMN media_duration DECIMAL(5,2) DEFAULT NULL;
```

## نصب و استقرار

1. `schema.sql` را یک‌بار روی دیتابیس اجرا کنید. برای نصب از `install.php` استفاده شده و بعد از نصب حذف شده است.
2. اطلاعات اتصال دیتابیس در `config.php` تنظیم شده است.
3. برای آپلود فایل‌های پروژه:

   ```bash
   python deploy.py
   ```

   `deploy.py` فایل‌های `install.php`، `schema.sql`، فایل‌های تست پایتون و آرشیوها را آپلود نمی‌کند.
4. پوشه `uploads` باید قابل نوشتن باشد. فایل `uploads/.htaccess` اجرای کد آپلودشده را مسدود می‌کند.

## تست

اسکریپت‌های تست فقط محلی هستند و نباید روی هاست آپلود شوند:

```bash
python _e2e_test.py       # تست کامل HTTP
python _security_test.py  # تست‌های امنیتی آپلود و CSRF
```

`_e2e_test.py` برای اجرا، دو حساب آزمایشی می‌سازد. بعد از تست، داده‌های آزمایشی را پاک کنید یا حساب‌ها را حذف کنید.

در بعضی بازه‌ها هاست رایگان پیش از پاسخ اصلی یک چالش JavaScript (`aes.js`) برمی‌گرداند؛ در این حالت `requests`/`curl` ممکن است به HTML چالش برخورد کنند. تست‌های مرورگری را از یک تب واقعی مرورگر (یا ابزار مرورگر) اجرا کنید. تست‌های استوری و تبدیل ویدیو به مرورگری نیاز دارند که `MediaRecorder` و `HTMLCanvasElement.captureStream` را پشتیبانی کند.

## محدودیت‌های شناخته‌شده

- رمزگذاری سرتاسری (E2E) وجود ندارد؛ پیام‌ها روی سرور ذخیره می‌شوند.
- ضبط صدا، تماس، مسدود کردن کاربر، نظرات کانال و برخی گزینه‌های حریم خصوصی در این نسخه فقط رابط کاربری/آماده‌ی توسعه‌اند.
- سنجاق کردن گفتگو در لیست، یک تنظیم محلی مرورگر است (localStorage) و بین دستگاه‌ها همگام نمی‌شود.
- نقش «نمایش به عنوان» در پنل اطلاعات، فقط نمایشی است؛ دسترسی واقعی را سرور تعیین می‌کند.
- هاست رایگان یک تبلیغ شناور به انتهای صفحات تزریق می‌کند؛ ممکن است روی موبایل بخشی از پایین صفحه را بپوشاند. این تبلیغ قابل بستن است و از سمت کد برنامه کنترل نمی‌شود.
- هاست رایگان به پاسخ‌های JSON هم HTML تبلیغاتی اضافه می‌کند؛ کلاینت فقط نخستین شیء JSON را می‌خواند.
- برای دارایی‌های ثابت از query string نسخه‌دار (`filemtime`) استفاده شده تا کش ۳۰روزه هاست مشکل ایجاد نکند.
- تبدیل ویدیو در مرورگر انجام می‌شود؛ مرورگرهای قدیمی یا بدون پشتیبانی WebM/MediaRecorder نمی‌توانند ویدیوی استوری بسازند.
- هاست `ffmpeg`/`exec` ندارد؛ بنابراین سرور خودِ مدت ویدیوی WebM را مستقل تجزیه نمی‌کند. محدودیت ۱۵ ثانیه در کلاینت و با بررسی مقدار `duration` ارسالی در سرور اعمال می‌شود. برای سوءاستفاده‌ی کامل باید در آینده تجزیه‌ی EBML یا سرویس تبدیل سمت سرور اضافه شود.
- پاک‌سازی ۲۴ ساعته‌ی استوری به cron وابسته نیست و فقط با درخواست‌های بعدی اجرا می‌شود؛ در سایت بدون ترافیک، حذف فایل‌ها ممکن است تا اولین درخواست بعدی عقب بیفتد.

## امنیت

- تمام پرس‌وجوهای دیتابیس با PDO و prepared statement انجام می‌شوند.
- عملیات تغییردهنده POST و همراه با `X-CSRF-Token` هستند.
- فایل‌های حساس مانند `config.php` و `schema.sql` با `.htaccess` مسدود شده‌اند.
- نام فایل‌های آپلودشده تصادفی است و پسوندهای اجرایی پذیرفته نمی‌شوند.
- رمز عبور با `password_hash` ذخیره می‌شود.
